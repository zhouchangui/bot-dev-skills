# /bot-auto — 全流程自动编排入口

目标：用户只需触发一次 `/bot-auto` 并描述需求，即由本编排器自动串起完整研发流水线，**通过有界“验证 ⇄ 审查 ⇄ 修复”收敛闭环确保目标彻底完成并自主提升质量**，只在大方向澄清、熔断与三道硬闸门处停下来交互。

## 断点嗅探、任务定级与智能跳步（减少阻力）

0. **断点续跑嗅探（Resume First）**：开工前先检查当前规格目录（{{TRACKER_HINT}}）与 `git status` 是否已存在当前任务的未完结 `spec.md`、`issues/` 切片进度或收敛账本；若存在，自动对齐已完成阶段并从上次停顿的切片、收敛轮次或硬闸门处直接续跑，严禁失忆重跑已确认阶段。
1. **10 秒定级并按路径推进**（不问用户）：

* **S 级（明确修复 / 纯文档或配置微调 / 单模块小改）**：
  - 仅**确定性 bug 修复、纯文档或纯配置微调**可直接跳过 `bot-think` 与 `bot-plan`；
  - 凡涉及**新增功能、新入口、新开关/配置项或新模块**（哪怕代码量很小），开工前必须先过一遍 30 秒的**第一性原理必要性速审**（根目标 + 能否靠删改/零代码替代 + `Option 0` 判词，存疑时走硬闸门 #1）；若涉及界面/样式/交互改动，同时核对 `DESIGN.md`/样式 token、界面模式（Marketing vs Workbench）、现代原生 Web 能力与交互五态。
  - 流程：`/bot-build`（或 `/bot-debug`）→ **质量收敛闭环（≤ 2 轮）** → `/bot-ship`。
* **M 级（标准新功能 / 跨文件改动 / 重构）**：
  - 完整流程：`/bot-think` → `/bot-plan` → `/bot-build` → **质量收敛闭环（≤ 3 轮）** → `/bot-ship`，并将目标验收矩阵与每轮收敛账本同步落盘到规格目录（{{TRACKER_HINT}}），防止跨轮上下文压缩或中断丢失进度。
* **L 级（大型多切片任务，预计 >3 个独立切片）**：
  - **内外双环与并发隔离**：先跑通 `/bot-think` 与 `/bot-plan` 落盘全部切片、`Touched Paths` 与 `Blocked by` 依赖；进入 `/bot-build` 前询问用户按顺序逐片推进还是并行分派（**仅当各切片 `Touched Paths` 无文件交集，或采用独立 `git worktree` 隔离时才允许并行分派**；触碰公共路由/Schema/共享类型的切片一律顺序推进）。每个切片落地后先完成局部测试与极简自检（内环），全部切片合拢后再执行全局**质量收敛闭环（≤ 3 轮，外环）**，全程将验收矩阵与轮次账本同步写入当前任务规格目录（{{TRACKER_HINT}}）。

## 质量收敛闭环（Verify ⇄ Review ⇄ Fix）

```text
/bot-build ──▶ /bot-verify ──(红灯/报错)──▶ /bot-debug（单点根因修复 + 回归锁定）──┐
                    │ (全绿 + 零新增告警)                                         │
                    ▼                                                            │
              /bot-review（独立冷视角：目标验收矩阵 + A/B/C/D + P0/P1/P2 分级）    │
                    │                                                            │
                    ├─ 触及架构/契约/新依赖/范围变更 ──▶ 停在【硬闸门 #1】        │
                    ├─ 命中熔断（达上限 / 连续2轮未收敛）──▶ 停下交用户裁决       │
                    ├─ 仍有 P0 或预算内可自主提升的 P1 ──▶ Test-Lock + 外科手术修复 ┘
                    └─ 满足全部退出条件 ──▶ 放行 /bot-ship【硬闸门 #3】
```

1. **显式目标验收矩阵（防“以为做完了”）**：进入闭环前，从用户原始需求、`spec.md` 与 `DESIGN.md`（若有）抽出逐条验收项（`AC-1..N`）。每轮审查必须逐条核对“代码实现 + 最新实测证据”，任一项缺失或无实测证据直接判 **P0**。
2. **先净空验证、再独立冷视角审查**：
   - 先跑 `/bot-verify`（含跨层真实往返契约校验与零新增告警/脏文件净空核对）；若有测试、构建或运行态失败，路由到 `/bot-debug`（复现红灯 → 单点根因修复 → 回归锁定），严禁在症状处盲打补丁。
   - `/bot-verify` 全绿后跑 `/bot-review`：**支持子代理的宿主对 M/L 级改动默认派干净上下文独立子代理执行审查**（隔离作者对话历史与主观推理；传入 `git diff <base>...HEAD` + 轮间增量 Diff + 验收矩阵 + `/bot-verify` 实测输出，同时开放代码库只读检索及 `AGENTS.md` / `DESIGN.md` 读取权限，以实证核查既有 helper 复用、上游调用链、热路径复杂度与设计对齐）；S 级或单代理宿主强制重读全量 diff 并按 A/B/C/D 分栏独立列证据。
3. **分级修复、先锁测试与最小爆炸半径（P0 / P1 / P2）**：
   - **P0（阻断级 · 必修且先补红灯测试）**：需求漏项/偏离、功能 bug、安全/边界漏洞、热路径严重 N+1/`O(N²)` 退化、不可逆迁移缺失兼容/回滚保护、verify 失败、UI 不可用/IME 误提交或缺失可恢复错态。**凡审查抓到的 P0 逻辑或边界缺陷，必须先补一条修复前报红、修复后变绿的回归测试（`Test-Lock then Fix`），禁止只改生产代码就重跑旧测试放行。**
   - **P1（质量提升级 · 预算内外科手术自主修）**：坏味道、违背极简与反退化四铁律（重复/早熟抽象/Middle Man/假默认值/类型强转）、薄弱测试（smoke-only 或后补测试未经反转证伪）、历史 Web 反模式（手写 `scrollHeight`/裸 `:invalid`/`max-height: 9999px`）或 UI 工艺瑕疵。第 1 轮清完 P0 后，若仍存在明显 P1，**主动在剩余预算内跑 1 轮质量抬升**再终验。
   - **轮间最小爆炸半径（Surgical Fix Budget）**：自第 2 轮起严格限制修改半径，只触碰被点名的 `P0/P1` 位置，**严禁顺手重排无关代码或跨模块顺带重构**；复审轮优先审查本轮增量 Diff 是否引入次生回归（Fix-Induced Regression）。
   - **P2（锦上添花 · 不触发新一轮）**：风格偏好、范围外顺手重构 → 只记录在交付摘要或延后待办，严禁为 P2 再开一轮改代码。
   - **反作弊红线**：严禁通过**删测试、弱化断言、加 `skip`、写空 `catch`、类型强转逃逸（`as any` / `as unknown as T` / `@ts-ignore`）或假默认值兜底（`?? 0` / `?? []` 掩盖契约错误）**来换取绿灯。
4. **轮次预算、状态账本与双熔断**：
   - **默认上限**：**S 级 ≤ 2 轮、M/L 级 ≤ 3 轮**；若用户明确要求“深度打磨 / 彻底跑透”，放宽至 **≤ 5 轮**。
   - **每轮 1 行账本**：`Round k/N | 验收 X/Y | Verify: PASS/FAIL | P0:a P1:b P2:c | 动作: fix/debug/stop`（M/L 级同步追加写入规格目录）。
   - **双熔断**：达到轮次上限，或**连续 2 轮同一问题反复出现 / `P0+P1` 总数不降反升** → 立即停止盲改，输出已尝试路径、根因卡点与决策选项交用户拍板。
5. **硬退出门槛（Exit Gate）**：仅当同时满足 ① 验收矩阵 **100% 闭环**；② **零 P0** 且预算内可自主解决的 **P1 已清零**；③ **最后一次修改代码之后**跑过一次全新、全绿且零新增告警/脏文件的 `/bot-verify` —— 方可放行进入 `/bot-ship`。

## 编排执行铁律

1. **按需读入阶段规范与单装兜底**：每次进入下一阶段时，用文件读取工具直接读取对应阶段文件（`{{STAGE_PATH_PATTERN}}`；若路径以 `../` 开头则相对于本 `SKILL.md` 所在目录解析，否则相对于项目根或 `~` 解析），严格执行其门禁与检查项；若用户仅按需单装了 `bot-auto` 而对应阶段文件不存在，则降级按本编排器内置的必要性审查、极简四铁律、收敛闭环与硬闸门直接执行，不要报错中断。
2. **UI 影响面强制激活（含现代原生 Web 规范）**：只要需求涉及页面、官网、组件、样式或前端交互，**务必按需读取 `{{UI_CRAFT_PATH}}`（若路径以 `references/` 开头则相对于本 `SKILL.md` 所在目录解析）并激活**界面模式判定（Marketing vs Workbench）、现代原生 Web 平台选型（`<dialog>` / `popover` / IME 守卫 / `:user-invalid` / Baseline 渐进增强）、`/bot-plan` 的 UI 与五态检查、`/bot-build` 的状态展示分离与微工艺落地、`/bot-review` 的维度 D 及 `/bot-verify` 的真实界面验收；纯后端/CLI 任务则自动跳过 UI 检查，零额外开销。
3. **不重复提问**：`/bot-think` 已经向用户确认过的问题与方案，自动带入 `/bot-plan` 与 `/bot-build`，严禁重复弹窗。
4. **只守三道硬闸门**：
   - **闸门 #1（重大决策）**：仅在 `/bot-think` 批量澄清+方案拍板时、或后续阶段/收敛环中发现未预见的跨模块/Schema/`One-way door`/新依赖/范围变更时停下来问。
   - **闸门 #2（建分支/worktree）**：在 `/bot-build` 动代码前，如需建分支或 worktree 必须先问确认；若用户明确要求直接在当前分支改则直接开工。
   - **闸门 #3（发布与合并）**：质量收敛闭环满足硬退出门槛后，在 `/bot-ship` 执行 `git push` / 创建或合并 PR / 部署前停下来展示证据、验收矩阵与轮次账本等用户拍板。
5. **复盘轻量收尾**：交付完成后，仅在本次确实暴露出“值得沉淀成 linter/hook/测试的重复坑”时，附带一句提示是否执行 `/bot-retro`；顺畅无坑时不打扰。
