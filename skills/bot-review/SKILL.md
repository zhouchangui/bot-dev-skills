# /bot-review — 对抗 + 双轴同构 + 深模块冗余 + UI 融合评审

目标：合并前结构化把关——同步核对目标验收闭环、线上稳定性与复杂度、架构同构一致性、深模块简洁度及（若涉 UI）`ui-craft.md` 工艺，按 `P0 / P1 / P2` 分级收敛。

## 通用流控与极简铁律

1. **澄清全正文，闸门可点选**：每题附默认推荐与理由，按**交互性质**分流：
   - **需求澄清与多轮追问（不限阶段/题数）**：一律用**正文分组编号清单**（`❓ Qn` + `➡️ 推荐`，支持回“全默认，仅改第 N 题”），输出后**立即停下等回复**，**严禁调用交互式提问弹窗**，严禁自问自答或代拍板；
   - **仅三道硬闸门与最终方案拍板**：这类 1–2 项离散确认点可用宿主交互多选工具（无工具则用正文）。
2. **三道硬暂停闸门（未获明确同意严禁执行）**：
   - **重大决策**：架构路线、公开契约/Schema、不可逆 `One-way door`、删核心范围、新依赖；
   - **建分支 / worktree**：`git checkout -b` / `git switch -c` / `git worktree add` 前确认分支名与基线；
   - **发布与合并**：`git push`、建/合 PR、发版构建或上线前。
   其余探索、测试、局部重构与修 bug 连续推进。
3. **极简与反退化四铁律**：
   - **复用阶梯**：`仓库既有 helper/模式 → 语言标准库 → 平台原生特性 → 已安装依赖`，高位能解即止步，禁擅加新包；
   - **三次法则（Rule of Three）**：同一逻辑 `< 3` 次且无第二真实调用方时不抽工厂/策略/包装层；
   - **零纯转发**：禁写透传参数的 Middle Man 与不可能状态的冗余兜底；
   - **反静默退化**：边界入参显式窄化，内部不变量损坏 Fail-Fast；**禁类型逃逸（`as any` / `as unknown as T` / `@ts-ignore` / `# type: ignore`）与假默认值投毒（`?? 0` / `?? ''` / `?? []` 掩盖契约断裂）**。
4. **宿主工具**：采用宿主中立表达：读取/编辑文件、执行终端命令、代码库检索；交互式多选工具仅用于硬闸门与最终方案拍板，所有需求澄清与追问一律正文输出。

## 审查范围与独立冷视角

1. 锁定 `git diff <base>...HEAD` + 未提交改动（第 2+ 轮同步提取**轮间增量 Diff**查次生回归），并读入用户原始目标、源 spec/ticket（项目 `.scratch/` 或 issue tracker）、项目规范（`AGENTS.md`/`GLOSSARY.md`/`DESIGN.md`/`docs/adr/`）与最新 `/bot-verify` 实测输出，列出**目标验收矩阵（`AC-1..N`）**。
2. **独立冷视角原则**：支持子代理的宿主对 **M/L 级改动默认派干净上下文独立子代理**执行审查（隔离作者历史；传入 diff、验收矩阵与 verify 输出，同时**开放代码库只读检索**及上述文档读取权限以核查同构模式、未改调用方与既有 helper）；S 级或单代理宿主强制重读全量 diff 按维度分栏列证据，禁笼统写“无问题”。

## 多维独立检查清单（不合并打分）

### 维度 A：Adversarial, Complexity & Production Failure
- **边界、权限与调用链**：越权、未校验输入、路径穿越/注入、空值/超限、并发竞争、部分写入恢复，以及**签名/行为变化后漏改的上游调用方**。
- **热路径复杂度与 I/O 放大**：循环内串行请求 / N+1、大集合隐式 `O(N²)`、无上限全量同步读入、高频整树重渲染或巨型包导入。
- **不可逆变更保护（One-way door）**：触及 Schema/本地持久化/公开契约变更时，缺兼容迁移或回滚路径直接判 P0。
- **失败可见性与反静默退化**：吞错、缺超时/未关句柄，或违背上方反静默退化铁律（类型强转消音 / 假默认值掩盖契约损坏）。

### 维度 B：Dual-Axis（目标验收、架构同构 & Standards）
- **目标验收与 Spec**：逐条核对 `AC-1..N` 代码与最新实测证据（缺项即 P0）；对照 `Out of Scope (Cut List)` 严查 Scope Creep。
- **架构同构一致性与封装边界**：只读对照同域老模块、`GLOSSARY.md` 与 `docs/adr/`——严查平行风格分裂、同概念异名、违背既有 ADR，以及**跨过模块公开入口私引内部子文件/私有状态**。
- **测试真伪与公开接缝**：测试只穿公开接口、覆盖失败路径且反转分支必红；跨层生产/消费同步改动必含无 Mock 往返契约测试。
- **Standards & 坏味道**：项目明文规范优先，次查重复逻辑、神秘命名、过长参数团、过长开关、霰弹枪修改（改一概念牵连 4–5 文件）与消息链过长（跳过 linter 已管格式项）。

### 维度 C：深模块与极简冗余审计
- **删除检验与浅模块**：新建模块/函数删掉后复杂度是否凭空消失（Middle Man）？是否仅为测内部步骤拆碎内聚逻辑导致胶水膨胀？
- **复用阶梯与单适配器禁令**：是否重造既有深模块/helper/标准库/原生能力？是否在**第 1/2 档本地依赖仅有 1 个实现（无第 2 个真实适配器；注：第 3/4 档跨网络/三方边界以“生产实现 + 测试替身”计为双适配器）**或不足 3 处调用（Rule of Three）时空造抽象层？
- **胶水与死代码**：>2 个纯透传文件、重构孤儿文件/死导出或不可能状态的冗余分支。

### 维度 D：UI 与交互审计（仅 diff 涉及页面/组件/样式/交互时对照 `references/ui-craft.md`——`references/` 相对本 `SKILL.md` 目录；否则写 `无 UI 改动，跳过`）
- **模式、独特性判词 & Skeleton Test**：先核对 Mode A（Marketing）还是 Mode B（Workbench），输出**独特性判词**并检验无文案骨架是否立得住。
- **现代原生 Web 反模式检查**（对照 `ui-craft.md` 第 5 节）：严查手写弹窗关窗、漏中文 IME 守卫、裸 `:invalid`、同步重排/魔法数字折叠、LCP 主图误懒加载或外链缺 SRI（保留存量刻意 `@supports` 兜底，勿盲删）。
- **设计工艺、五态与反套路红线**（对照 `ui-craft.md` 第 1–4、6 节）：核查 `DESIGN.md` 对齐、浏览面/动效/GPU 约束、边缘五态与 `1440/768/390` 多断点，及反 AI 默认皮肤与容器红线；Fix-First 按 **`提纯 / 降噪 / 强化 / 打磨`** 四动词修复。

## 分级与修复规则

- **分级**：
  - **P0（阻断 · 先锁红灯再修）**：验收缺项/无实证、功能/安全/边界缺陷、违背 ADR 硬约束、严重复杂度退化、`One-way door` 缺回滚、验证失败、IME 误提交或 UI 不可用/缺可恢复错态；
  - **P1（质量提升 · 外科手术自主修）**：同构风格分裂、跨公开入口私引、浅模块/违背极简铁律、弱测/假阳性测试、历史 Web 反模式、UI 工艺/五态瑕疵；
  - **P2（只记不改）**：风格偏好或范围外存量模块加深机会，记入待办不开新轮。
- **执行红线**：P0 逻辑/边界缺陷一律 **`Test-Lock then Fix`**（先补红灯回归测试再修）；P1 最小化修复，禁顺手重排无关代码；改代码后必重跑 `/bot-verify`；严禁删测/弱断言/`skip`/空 `catch`/类型强转/假默认值换绿灯；跨模块架构/契约/`One-way door`/新依赖/范围取舍停在**硬闸门 #1**。
- **分栏输出**：分栏列 `Goal Acceptance (AC-1..N)`、`Adversarial`、`Spec & Standards`、`Bloat Audit`（及 UI 时的 `UI & UX Audit`）的 `P0/P1/P2` 计数、实证与修复结果，禁捏造未验证输出。
