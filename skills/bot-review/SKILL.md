# /bot-review — 对抗 + 双轴同构 + 深模块冗余 + UI 融合评审

目标：合并前把关。用一次结构化审查同时核对**目标验收是否彻底闭环**、系统会不会在线上炸或变慢、**架构风格与既有代码是否同构一致**、模块边界是否深且干净，以及（若改到界面）设计系统、现代原生 Web 实践与交互五态是否到位，按 `P0 / P1 / P2` 分级收敛修复。

## 通用流控与极简铁律

1. **业务问透优先，按场景与题量分流（别乒乓，更不削足适履）**：澄清问题时每题给出默认推荐与理由，**严禁为迁就交互弹窗的题数/字数上限而合并、删减业务问题或把开放题硬改选择题**：
   - **`/bot-think` 决策树多轮追问、> 4 题、含开放性业务问题，或宿主无交互工具**：全程改用**正文分组编号清单**（`❓ Qn` + `➡️ 推荐`，标清默认推荐，支持用户按题号回“全默认，仅改第 N 题”），输出后**立即结束本轮等待用户回复**，严禁同轮混用截断式弹窗，严禁自问自答或替用户暗自拍板；
   - **方案拍板或下游阶段 ≤ 4 个独立离散选择题**：直接用宿主交互式多选工具一次点选。
2. **三道硬暂停闸门（未经用户明确同意，严禁自行执行）**：
   - **重大决策**：架构路线、模块公开契约/Schema 变更、不可逆 `One-way door` 变更、删减核心范围、引入新依赖或不可逆操作。
   - **创建分支或 worktree**：执行 `git checkout -b` / `git switch -c` / `git worktree add` 前必须先询问确认分支名与基线。
   - **发布与合并**：执行 `git push`、创建/合并 PR、发版构建或线上部署前必须先询问确认。
   其余探索、测试、局部重构与修 bug 连续推进，不要琐碎弹窗打断心流。
3. **极简编码与反退化四铁律（写任何代码前先过一遍）**：
   - **复用阶梯**：`仓库已有 helper / 模式 → 语言标准库 → 平台原生特性（如原生 HTML/CSS、DB 约束）→ 已安装依赖`，在最高一层能解决就止步，严禁未经确认新增包。
   - **三次法则（Rule of Three）**：同一逻辑未真实出现 3 次且无第二个真实调用方时，禁止提前抽工厂、策略类、通用配置层或猜测性抽象。
   - **零纯转发**：禁止写只透传参数的中间转发函数（Middle Man），禁止为不可能发生的内部状态写冗余兜底分支。
   - **严禁类型逃逸与假默认值投毒**：系统边界入参必须显式窄化校验，内部不变量损坏必须快速失败（Fail-Fast）；**严禁用双层类型强转（`as any` / `as unknown as T` / `@ts-ignore` / `# type: ignore`）消音，严禁用 `?? 0`、`?? ''`、`?? []` 把上游契约断裂静默吞成合法假数据**。
4. **宿主交互与工具映射**：采用宿主中立表达：读取/编辑文件、执行终端命令、代码库检索、向用户批量提问（≤4 个独立选择题用交互式多选工具；超 4 题、含开放性业务问题或无工具时用正文分组编号清单等待用户回复，业务问清楚优先）。

## 审查范围锁定

1. 确定对比基准（`git diff <base>...HEAD` + 未提交改动；若处于第 2+ 轮收敛修复，同步提取**上一轮至本轮的增量 Diff**重点核查修复是否越界或引入次生回归）。
2. 同步读入用户原始目标、源 spec / ticket（项目 `.scratch/` 或 issue tracker）、项目规范/领域文档（如 `AGENTS.md`、`GLOSSARY.md`、`DESIGN.md`、`docs/adr/`）以及最新 `/bot-verify` 实测输出，列出**目标验收矩阵（`AC-1..N`）**作为核对依据。

## 多维独立检查清单（不合并打分）

> **独立冷视角原则**：支持子代理的宿主对 **M/L 级改动默认派干净上下文独立子代理**执行审查（隔离作者对话历史与主观推理；传入 `git diff <base>...HEAD` + 验收矩阵 + `/bot-verify` 实测输出，同时开放代码库只读检索及 `AGENTS.md` / `GLOSSARY.md` / `DESIGN.md` / `docs/adr/` 读取权限，以实证核查邻近同构模式、未改调用方与既有 helper）；S 级或单代理宿主强制重读全量 diff，按 **目标验收 → 维度 A → B → C（→ D）** 依次独立核查并分栏输出，严禁笼统写“已检查无问题”。

### 维度 A：Adversarial, Complexity & Production Failure（攻击者、复杂度与混沌视角）
- **边界、权限与调用链**：越权访问、未校验输入、路径穿越、注入、空值/超大负载、并发竞争、部分写入崩溃恢复，以及**签名/行为变化后未同步更新的上游调用方**。
- **热路径复杂度与 I/O 放大**：是否存在循环内串行请求 / N+1 查询、大集合嵌套查找导致的隐式 `O(N²)`、无上限全量同步读入内存，或高频交互路径整树重渲染与巨型包导入？
- **不可逆变更保护（One-way door）**：若触及 DB Schema、本地持久化格式或公开契约变更，核查是否具备兼容读取/迁移与回滚路径（缺失即判 P0）。
- **失败可见性与反静默退化**：是否存在错误被静默吞掉、超时未设、句柄未关闭，或通过类型强转（`as any` / `as unknown as T` / `@ts-ignore`）与假默认值（`?? 0` / `?? []`）掩盖契约损坏？

### 维度 B：Dual-Axis（目标验收、架构同构一致性 & Standards）
- **目标验收与 Spec 符合度**：① 逐条核对 `AC-1..N` 是否均有代码实现与最新实测证据（缺一项即 P0）；② 偏离规格的行为；③ 对照 `Out of Scope (Cut List)` 严查未被要求的 **Scope Creep（额外加戏）**。
- **架构同构一致性与封装边界（Consistency & Locality）**：只读对照同域既有模块、`GLOSSARY.md` 与 `docs/adr/`——① 新代码是否在目录分层、错误返回格式、配置传递与领域词汇上与老代码保持同构（严查**同一仓库分裂出两套平行风格或同概念异名**，以及违背既有 ADR 的实现）？② 是否存在**跨过其他模块公开入口直接私引内部子文件/读写私有状态**的破窗行为？
- **测试真伪与公开接缝纪律**：测试是否只穿过公开接口（禁绑死内部私有实现细节）、覆盖失败路径且反转实现分支会报红（杜绝 smoke-only 与永真断言）？跨边界生产/消费同步改动是否具备无 Mock 往返契约测试？
- **Standards & 代码坏味道**：先看仓库明文规范（优先级最高），再对照常见坏味道：**重复逻辑、神秘命名、过长参数团（Data Clumps）、过长开关分支、霰弹枪式修改（Shotgun Surgery：改一处概念牵连 4–5 个文件）、消息链过长**。跳过 linter 已自动检查的格式项。

### 维度 C：深模块与极简冗余审计（Deep-Module & Bloat Audit）
- **删除检验（Deletion Test）与浅模块排查**：新建模块/函数删掉后复杂度是凭空消失（浅层透传壳 / Middle Man）还是退回多处调用方？是否存在单纯为了测内部步骤而拆碎纯函数导致调用方拼装胶水膨胀？
- **复用阶梯与单适配器禁令**：是否重写了仓库已有深模块/helper、标准库或平台原生能力？是否在仅有 1 个实现（无第 2 个真实适配器）或不足 3 处调用（Rule of Three）时空造了 Interface / Port / Factory 间接层？
- **胶水与死代码**：是否存在 >2 个纯透传胶水文件、重构后遗留的孤儿文件/未使用导出，或为不可能状态编写的冗余防御分支？

### 维度 D：UI 与交互审计（含现代原生 Web 规范，仅 diff 涉及页面 / 组件 / 样式 / 交互时必查，对照 `references/ui-craft.md`——若路径以 `references/` 开头则相对于本 `SKILL.md` 所在目录解析；否则写 `无 UI 改动，跳过`）
- **界面模式、独特性判词 & Skeleton Test**：先核对页面属于 **Mode A（Marketing 叙事面）** 还是 **Mode B（Workbench 工具台面）**（勿拿官网大留白苛求高频工具台，也勿拿工具台密度堆砌官网），再明确判定“抽掉品牌名和文案，是否一眼像同类可互换模板？无文案骨架主次是否立得住？”
- **现代原生 Web 反模式检查**：是否写了本可用原生能力替代的历史 Hack——如每次输入读 `scrollHeight` 撑高文本框（应改 `field-sizing: content`）、`Enter` 提交漏加 `e.isComposing || e.keyCode === 229` 中文输入法守卫、用裸 `:invalid` 导致首屏未交互先标红（应改 `:user-invalid`）、手写 `e.target === dialog` 关弹窗（应改原生 `<dialog>` / `popover`）、`max-height: 9999px` 折叠假动画、首屏 LCP 主图误加 `loading="lazy"` 或外链 CDN 缺 `integrity`（SRI）？（注意保留存量代码中有意的 `@supports` 兼容兜底，勿盲删安全降级。）
- **设计与微工艺偏移**：是否违背 `DESIGN.md`、出现硬编码色/间距、彩底灰字、漏改 `::selection`/`:focus-visible` 浏览面，或违背物理动效与 GPU 约束（出现 `ease-in`/`linear` 入场、容器+子项双重延迟、大面积滚动 `backdrop-blur`）？
- **边缘五态与多断点**：空态、加载态、错态（可恢复）、长文本溢出与首用态是否遗漏？`1440 / 768 / 390` 等视口下是否错位、低对比或不可键盘操作？
- **反套路视觉红线**：是否出现**卡片套卡片**、AI 默认皮肤、三栏彩色圆圈图标网格、标题上方全大写小药丸、`→`/`↗` 装饰按钮、暗底霓虹光晕或假指标占位？Fix-First 按 **`提纯 / 降噪 / 强化 / 打磨`** 四动词精准修复。

## 分级、先锁测试与外科手术修复规则

- **严重级分流（`P0 / P1 / P2`）**：
  - **P0（阻断 · 先锁红灯再修）**：验收项遗漏/无实测证据、功能 bug、安全/边界漏洞、违背既有 ADR 硬约束、严重 N+1/`O(N²)` 退化、不可逆变更缺失兼容/回滚保护、验证失败、IME 误提交/UI 不可用或缺失可恢复错态；
  - **P1（质量提升 · 外科手术自主修）**：架构风格分裂（与邻近模块分层/错误格式/领域名词不一致）、跨过模块公开入口私引内部文件、浅模块/违背删除检验或极简四铁律、薄弱或假阳性测试、历史 Web 反模式、UI 独特性/微排版/五态/动效瑕疵；
  - **P2（锦上添花 · 只记录不改）**：风格偏好或范围外存量模块加深机会，记入交付说明/待办，不触发新改代码轮次。
- **`Test-Lock then Fix`、最小爆炸半径与反作弊红线**：
  - 凡抓到的 **P0 逻辑或边界缺陷**，必须**先补一条修复前报红、修复后变绿的回归测试**再改实现；局部明确的 P1 直接最小化修复，**严禁顺手重排未点名的无关代码**（凡修改了代码，后续必须重新执行 `/bot-verify`）；
  - **严禁通过删测试、弱化断言、加 `skip`、空 `catch`、类型强转逃逸或假默认值兜底来换取通过**。
- **硬闸门 #1**：凡涉及改变跨模块架构、公开接口、`One-way door` 迁移方案、新依赖、范围取舍或不确定意图的问题，停下来列成选项交用户拍板。
- **输出分栏**：分别报告 `Goal Acceptance (AC-1..N)`、`Adversarial`、`Spec & Standards`、`Bloat Audit`（以及涉及 UI 时的 `UI & UX Audit`）的 `P0/P1/P2` 计数、发现与修复结果，严禁捏造未验证的行号或输出。
