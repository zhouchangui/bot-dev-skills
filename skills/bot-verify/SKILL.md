# /bot-verify — 确定性验证与安全门禁

目标：用**真实命令输出、跨层契约实测与零新增告警净空证据**证明改动可安全交付；没有在最后一次代码修改后实跑的检查，一律不得宣称通过。

## 通用流控与极简铁律

1. **业务问透优先，按场景与题量分流（别乒乓，更不削足适履）**：澄清问题时每题给出默认推荐与理由，**严禁为迁就交互弹窗的题数/字数上限而合并、删减业务问题或把开放题硬改选择题**：
   - **`/bot-think` 决策树多轮追问、> 4 题、含开放性业务问题，或宿主无交互工具**：全程改用**正文分组编号清单**（`❓ Qn` + `➡️ 推荐`，标清默认推荐，支持用户按题号回“全默认，仅改第 N 题”），输出后**立即结束本轮等待用户回复**，严禁同轮混用截断式弹窗，严禁自问自答或替用户暗自拍板；
   - **方案拍板或下游阶段 ≤ 4 个独立离散选择题**：直接用宿主交互式多选工具一次点选。
2. **三道硬暂停闸门（未经用户明确同意，严禁自行执行）**：
   - **重大决策**：架构路线、模块公开契约/Schema 变更、不可逆 `One-way door` 变更、删减核心范围、引入新依赖或不可逆操作。
   - **创建分支或 worktree**：执行 `git checkout -b` / `git switch -c` / `git worktree add` 前必须先询问确认分支名与基线。
   - **发布与合并**：执行 `git push`、创建/合并 PR、发版构建或线上部署前必须先询问确认。
   其余探索、测试、局部重构与修 bug 连续推进，不要琐碎弹窗打断心流。
3. **极简编码与反退化四铁律（写任何代码前先过一遍）**：
   - **复用阶梯**：`仓库已有 helper / 模式 → 语言标准库 → 平台原生特性（如原生 HTML/CSS、DB 约束）→ 已安装依赖`，在最高一层能解决就止步，严禁未经确认新增包。
   - **三次法则（Rule of Three）**：同一逻辑未真实出现 3 次且无第二个真实调用方时，禁止提前抽工厂、策略类、通用配置层或猜测性抽象。
   - **零纯转发**：禁止写只透传参数的中间转发函数（Middle Man），禁止为不可能发生的内部状态写冗余兜底分支。
   - **严禁类型逃逸与假默认值投毒**：系统边界入参必须显式窄化校验，内部不变量损坏必须快速失败（Fail-Fast）；**严禁用双层类型强转（`as any` / `as unknown as T` / `@ts-ignore` / `# type: ignore`）消音，严禁用 `?? 0`、`?? ''`、`?? []` 把上游契约断裂静默吞成合法假数据**。
4. **宿主交互与工具映射**：采用宿主中立表达：读取/编辑文件、执行终端命令、代码库检索、向用户批量提问（≤4 个独立选择题用交互式多选工具；超 4 题、含开放性业务问题或无工具时用正文分组编号清单等待用户回复，业务问清楚优先）。

## 执行清单

1. **项目级检查与真实运行验收**：
   - **全仓基线检查（必跑）**：执行类型检查与测试套件（项目 typecheck/test）；若未显式配置，自动识别 `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` / `Makefile` 中的 check/test 命令实跑，均无则如实汇报 `未配置检查命令`。
   - **按变更影响面触发端到端验收**：若改动涉及前端界面 / 客户端 / 服务端 / 运行态 / 构建脚本，执行 项目集成/冒烟验证（涉及 Web UI 时按项目允许的真实运行入口核查视觉布局、交互五态、`<dialog>`/`popover` 焦点锁定与 `Esc` 关闭、中文 IME 回车防误触、`prefers-reduced-motion` 降级及零布局偏移 CLS，严禁越过项目环境禁令）；纯文档或无关子模块改动可跳过并在证据中写明原因，不拖慢心流。
2. **变更敏感面安全自检（若涉及鉴权/支付/网络/文件/外部输入/Web DOM）**：
   - **密钥与敏感信息**：无硬编码秘钥，且密钥/Token 不进日志、报错或 URL 查询参数；
   - **认证与鉴权边界**：Fail-Closed，默认拒绝而非放行，服务端二次校验归属权；
   - **注入、DOM 与子资源边界**：SQL/Shell 参数化、不可信 HTML 经 Sanitizer / Trusted Types 过滤（禁裸 `innerHTML`）、外链 CDN 资源具备 `integrity`（SRI）、路径 `path.resolve`/`realpathSync` 防穿越、防 SSRF（禁止未校验用户 URL 直连内网）；
   - **外部请求韧性**：显式超时与非 2xx 异常状态处理。
3. **测试真伪与跨层往返核对**：
   - 检查新增测试是否真正保护了公开边界行为与失败路径（反转关键分支会报红），而非只测“不报错（smoke-only）”或复制实现逻辑；
   - 核对跨层契约变更（前后端、序列化读写、CLI 参数）是否包含至少 1 条无 Mock 真实往返测试。
4. **零新增噪音与工作区净空核对（Zero Net-New Warnings & Diff Hygiene）**：
   - 即使退出码为 `0`，也必须检查命令输出是否新增了 `Warning / Deprecation / UnhandledRejection / console.error`；
   - 对照 `git status` 与 `git diff` 确认无遗留的调试打印（`console.log` / `debugger`）、Spike 临时文件、未纳入测试的孤儿新文件或重构遗留死文件。
5. **证据输出格式**：
   - 必须如实列出：**实际跑了什么命令 + 通过/失败/跳过计数 + 新增告警与工作区净空核对结论 + 未覆盖项与原因**。任何跳过或未跑的环节必须标明，禁止用旧截图或记忆代替实测。
